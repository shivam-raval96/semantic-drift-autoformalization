Learning to recognize a formal notation by name

Stage 1 · Llama‑3.1‑8B · recognition only (no translation)

Question

We took three different formal notations for writing the same kind of math and gave each a meaningless name. Nothing in the model's input says what the names mean. Can the model learn, from examples alone, to tell the notations apart by name and to check whether a statement really belongs to a named notation?

The three notations and their labels

Each notation is referred to only by an arbitrary label — RG-1, RG-2, RG-3 — chosen so the model cannot guess meaning from the name and must learn it from examples.

  • RG-1 and RG-2 are two prefix-style notations (the operation is written before its inputs).
  • RG-3 is an infix-style notation (the operation is written between its inputs).

How we built the dataset

  • We started from a fixed bank of formal statements whose correct notation and validity are known exactly — a deterministic program writes each statement, so no human or model ever labels anything.
  • Each statement is rendered into all three notations, giving matched examples across RG-1, RG-2, RG-3.
  • We split by underlying problem: a problem's statements go entirely to training or entirely to the test. The test therefore uses problems the model never saw in training, so it cannot succeed by memorizing.
  • 1,800 training examples and 495 test examples, balanced evenly across the three labels and across valid/invalid answers.

The two tasks

  • Name the notation. Given a statement, output its label (RG-1, RG-2, or RG-3).
  • Judge validity. Given a statement and a label, answer Yes or No: is this a genuine example of that notation? Invalid cases were built three ways — a statement from a different notation, broken syntax, or the right notation carrying the wrong internal labels.

Setup

Base model
Llama-3.1-8B-Instruct
Fine-tuning
LoRA, rank 16, all layers
Learning rate
2e-4, cosine schedule, 3% warmup
Training length
3 epochs (~675 steps), effective batch size 8
Objective
loss on the answer only (the question is masked)
Evaluation
greedy decoding on the 495 held-out examples

What it means

A model can learn to attach an arbitrary name to a formal notation from examples alone, and does so completely — every held-out case correct, including the hardest ones (well-formed statements labelled with the wrong notation).

Because accuracy reaches 100%, recognition is easy once taught. The open question it sets up: does teaching this familiarity first help the model do the harder job of faithful translation, and does it carry over to notations never trained on?
